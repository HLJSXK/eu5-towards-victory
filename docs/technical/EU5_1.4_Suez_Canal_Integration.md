# EU5 1.4 苏伊士运河原生机制接入记录

状态：调查完成，待实现

目标版本：EU5 1.4 beta 参考环境；正式 1.4 发布后必须重新同步并复核原版文件。

## 结论

EU5 1.4 的原生运河机制可以为 Towards Victory 的苏伊士奇观提供真实的海军通行连接。推荐保留现有 `unique_suez_ancient_canal` 奇观、仪式、建筑和经济奖励，只把“完成后真正打通地中海与红海”的部分接入原生 Canal Manager。

原生机制不能由地点修正、国家修正或普通奇观建筑单独模拟。它依赖地图中预先登记的 `canal` 邻接，并由引擎根据运河开放、战争和限制状态决定该邻接是否可通行。

## 1.4 原生机制

### 地图拓扑

1.4 参考文件 `reference_game_files/game/in_game/map_data/adjacencies.csv` 已登记：

```text
bardawil_coast;gulf_suez;canal;suez;9168;5106;9173;5029;Suez Canal - TBD pixel coords from map team
```

字段含义为 `From;To;Type;Through;...`。苏伊士运河连接 `bardawil_coast` 与 `gulf_suez`，由 `suez` 作为 through-location。

这条邻接是固定地图数据，不是脚本运行时创建或删除的边。因此目标环境必须使用包含该行的 1.4 地图数据；如果本 mod 覆盖 `adjacencies.csv`，必须保留该记录。

### 引擎状态

`common/generic_actions/canal_actions.txt` 的注释说明，`CCanalManager::IsCanalAccessible` 会在战争期间自动阻挡敌方。`is_canal_restricted` 是额外限制，只允许盟友、附庸和宗主等关系通过。

1.4 官方脚本变更记录 `reference_official_defines/changes_script_docs.md` 新增：

| API | 作用 |
| --- | --- |
| `set_canal_open` | 打开或关闭当前地点经过的运河；地点必须是 `adjacencies.csv` 中登记的 canal through-location。 |
| `start_canal_construction` | 在当前地点启动原生运河施工。 |
| `is_canal_open` | 检查运河是否已建成并开放。 |
| `has_canal_construction` | 检查地点是否正在进行运河施工。 |
| `set_canal_restricted` | 设置仅盟友/臣属/宗主可通过的限制。 |
| `is_canal_restricted` | 检查运河限制状态。 |

因此动态行为是“固定邻接 + 引擎可通行判定”，而不是动态修改地理、地点修正或海域连接。

### 原版施工链

`common/decisions/canal_construction.txt` 中的 `build_suez_canal` 要求：

- 200,000 gold；
- 拥有 `tinnis` 和 `suez`，或由符合条件的非主权臣属拥有；
- 已研究 `suez_canal_advance`；
- `location:suez` 尚未开放且没有正在施工。

决议效果调用：

```text
location:suez = {
    start_canal_construction = { }
}
```

`suez_canal_advance` 位于 `common/advances/canal_advances.txt`，属于 `age_5_absolutism`，并要求 `pound_lock_canals_advance` 和苏伊士地点控制。

### 战争限制清理

`common/on_action/_hardcoded.txt` 的 `on_ending_war` 会对每个拥有的、处于限制状态的运河执行：

```text
set_canal_restricted = no
```

未来接入时应依赖这一原生清理逻辑，不要在 Towards Victory 中复制一套战争结束清理，除非测试证明目标版本行为发生变化。

## 当前 Towards Victory 实现

苏伊士奇观定义位于 `data/unique_wonders.yaml:4268` 附近：

- key：`unique_suez_ancient_canal`；
- 固定地点：`suez`；
- 基础机制：`large_canal_system`；
- 完成建筑：`tv_wonder_unique_suez_ancient_canal_inaugurated`；
- 仪式：`canal_opening`；
- 初始等级为 0，最终建筑最高 6 级。

当前实现已经提供奇观系统本身的施工、仪式和奖励，但没有调用任何原生运河 API。主要效果包括：

- 基础奇观的全球繁荣和臣属倾向：`data/wonder_base_modifiers.yaml:69-71`；
- 最终建筑的地点发展和传播速度：`data/wonder_final_buildings.yaml:251-254`；
- 最终建筑的地点文化、发展、繁荣和臣属效果：`src_engineering_department/in_game/common/building_types/tv_engineering_department_wonder_mechanics_buildings.txt:18286` 附近；
- 苏伊士仪式的 `tax_income_efficiency = 0.05`：`src_engineering_department/in_game/common/static_modifiers/tv_engineering_department_wonder_mechanics_modifiers.txt:5989`；
- 按奇观等级缩放的自动修正：`src_engineering_department/in_game/common/auto_modifiers/tv_engineering_department_wonder_mechanics_auto_modifiers.txt:1091` 附近。

这些效果不改变舰队寻路，因此当前“苏伊士运河”尚未提供原生意义上的跨运河海军通行。

## 推荐接入方案

### 方案 A：奇观完成时直接开放原生运河（推荐）

保留 Towards Victory 自己的奇观施工和 `canal_opening` 仪式。在苏伊士最终完成效果的隐藏分支中，对 `location:suez` 调用：

```text
location:suez = {
    set_canal_open = yes
}
```

建议接入的生成源是 `data/unique_wonders.yaml` 与对应的奇观最终化生成器，而不是直接修改生成文件 `src_engineering_department/in_game/common/scripted_effects/tv_wonder_finalization_effects.txt`。

完成效果目前集中在生成输出：

- `tv_wonder_unique_suez_ancient_canal_style_1_construct_final_building_effect`；
- `tv_wonder_unique_suez_ancient_canal_style_1_finalization_hidden_effect`；
- `tv_wonder_unique_suez_ancient_canal_finalization_visible_effect`。

应确保 `set_canal_open = yes` 只在最终完成确认后执行，而不是在中间模块、仪式阶段或预览效果中执行。

### 方案 B：奇观启动时调用原生施工（不推荐）

不建议在 Towards Victory 奇观开始时调用 `start_canal_construction`。这会并行存在两套施工系统：奇观自己的阶段/成本/进度和原生运河施工/完成状态，可能导致重复花费、重复时间、状态不同步和完成顺序不确定。

只有在决定完全放弃现有苏伊士奇观施工，改为包装原版 `build_suez_canal` 决议时，才应考虑该方案。

## 需要先作出的设计决定

### 原版决议是否保留

1.4 原版 `build_suez_canal` 仍然存在。实现前必须选择：

1. **共存**：原版决议和 Towards Victory 奇观都可以开放苏伊士；需要接受两条内容路径可能产生不同奖励。
2. **奇观专属**：覆盖或限制原版决议，使苏伊士只能由奇观完成效果开放；需要同步处理 AI 和决议可见性。
3. **原版施工、奇观奖励**：允许原版运河先开放，但奇观只提供建筑、仪式和经济奖励；此时奇观完成不能无条件重复调用 `set_canal_open` 之外的施工接口。

默认建议是先采用“共存”进行最小风险验证，再根据设计目标决定是否覆盖原版决议。

### 运河被摧毁时是否关闭

原生 `set_canal_open` 是地点状态，未自动绑定到 Towards Victory 建筑生命周期。需要明确：

- **永久工程**：奇观完成后永久保持开放；最终建筑摧毁只移除奇观奖励，不关闭运河。
- **建筑即通航权**：最终建筑摧毁时执行 `set_canal_open = no`，重建后再次开放。

默认建议采用“永久工程”。这更符合原生运河“建成后存在”的模型，也避免所有权转移或建筑损坏时出现不可预期的海军路径断裂。若采用建筑绑定，必须额外实现并测试摧毁、重建、地点转手和存档加载。

### 奇观地点是否必须固定为 `suez`

当前奇观固定为 `suez`，原生地图邻接也只注册 `suez`。未来不要把该奇观改为任意地点，除非同时新增对应的地图 canal 邻接并确认 1.4 引擎允许该扩展。仅通过脚本把奇观移动到别的地点不能迁移原生运河。

## 风险与边界

- 当前证据来自同级 `eu5-modding-project` 的 EU5 1.4 beta 参考文件，不等同于最终正式版。
- Canal Manager 的核心可通行判定在 C++ 中，脚本只能调用公开状态和效果接口，不能重写其关系判断。
- `canal` 邻接属于地图数据；没有对应邻接时，`set_canal_open` 不能凭空创建跨海通路。
- 奇观的经济、贸易、地点发展和仪式奖励仍属于 Towards Victory 逻辑，原生运河只替代真实通行状态。
- 本文是实现登记，不代表功能已经接入；在完成代码、生成、日志和实际游戏测试前，不应宣称苏伊士已经具备原生通航能力。
