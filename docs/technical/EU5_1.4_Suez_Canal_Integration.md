# EU5 1.4 苏伊士运河原生机制接入记录

状态：建筑绑定代码、数据和生成输出已实现，静态规则与项目校验通过；尚未部署或启动游戏，实际通航验收待执行。

目标版本：EU5 1.4 beta 参考环境；正式 1.4 发布后必须重新同步并复核原版文件。

## 结论

EU5 1.4 的原生运河机制已接入 Towards Victory 的苏伊士奇观。保留现有奇观施工、仪式、建筑和经济奖励，实际通行状态由原生 Canal Manager 处理。

用户已确认：保留原版 `build_suez_canal` 决议；TV 最终建筑真实完成后开放，拆除最后一级后关闭，部分降级保留通航，重建完成后开放。即使原版过去已经建成，TV 最后一级拆除仍关闭；原版后续完工可以重新开放。不记录建成来源。

原生机制不能由地点修正、国家修正或普通奇观建筑单独模拟。它依赖地图中预先登记的 `canal` 邻接，并由引擎根据运河开放、战争和限制状态决定该邻接是否可通行。

## 1.4 原生机制

### 地图拓扑

1.4 参考文件 `reference_game_files/game/in_game/map_data/adjacencies.csv` 已登记：

```text
bardawil_coast;gulf_suez;canal;suez;9168;5106;9173;5029;Suez Canal - TBD pixel coords from map team
```

字段含义为 `From;To;Type;Through;...`。苏伊士运河连接 `bardawil_coast` 与 `gulf_suez`，由 `suez` 作为 through-location。

这条邻接是固定地图数据，不是脚本运行时创建或删除的边。因此目标环境必须使用包含该行的 1.4 地图数据；如果本 mod 覆盖 `adjacencies.csv`，必须保留该记录。

### 引擎状态

`common/generic_actions/canal_actions.txt` 的注释说明，`CCanalManager::IsCanalAccessible` 会在战争期间自动阻挡敌方。`is_canal_restricted` 是额外限制，只允许盟友、附庸和宗主等关系通过。

1.4 官方脚本变更记录 `reference_official_defines/changes_script_docs.md` 新增：

| API | 作用 |
| --- | --- |
| `set_canal_open` | 打开或关闭当前地点经过的运河；地点必须是 `adjacencies.csv` 中登记的 canal through-location。 |
| `start_canal_construction` | 在当前地点启动原生运河施工。 |
| `is_canal_open` | 检查运河是否已建成并开放。 |
| `has_canal_construction` | 检查地点是否正在进行运河施工。 |
| `set_canal_restricted` | 设置仅盟友/臣属/宗主可通过的限制。 |
| `is_canal_restricted` | 检查运河限制状态。 |

因此动态行为是“固定邻接 + 引擎可通行判定”，而不是动态修改地理、地点修正或海域连接。

### 原版施工链

`common/decisions/canal_construction.txt` 中的 `build_suez_canal` 要求：

- 200,000 gold；
- 拥有 `tinnis` 和 `suez`，或由符合条件的非主权臣属拥有；
- 已研究 `suez_canal_advance`；
- `location:suez` 尚未开放且没有正在施工。

决议效果调用：

```text
location:suez = {
    start_canal_construction = { }
}
```

`suez_canal_advance` 位于 `common/advances/canal_advances.txt`，属于 `age_5_absolutism`，并要求 `pound_lock_canals_advance` 和苏伊士地点控制。

### 战争限制清理

`common/on_action/_hardcoded.txt` 的 `on_ending_war` 会对每个拥有的、处于限制状态的运河执行：

```text
set_canal_restricted = no
```

当前实现依赖这一原生清理逻辑，没有复制战争结束清理流程。

## 当前 Towards Victory 实现

苏伊士奇观定义位于 `data/unique_wonders.yaml`：

- key：`unique_suez_ancient_canal`；
- ID：129；原生接入字段：`native_canal: true`；
- 固定地点：`suez`；
- 基础机制：`large_canal_system`；
- 完成建筑：`tv_wonder_unique_suez_ancient_canal_inaugurated`；
- 仪式：`canal_opening`；
- 初始等级为 0，最终建筑最高 6 级。

原有施工、仪式和奖励保留；新增通航调用位于完成与拆除的延迟位置回调。既有奖励来自：

- 基础奇观的全球繁荣和臣属倾向：`data/wonder_base_modifiers.yaml`；
- 最终建筑的地点发展和传播速度：`data/wonder_final_buildings.yaml`；
- 最终建筑的地点文化、发展、繁荣和臣属效果：`tv_engineering_department_wonder_mechanics_buildings.txt`；
- 苏伊士仪式的 `tax_income_efficiency = 0.05`：`tv_engineering_department_wonder_mechanics_modifiers.txt`；
- 按奇观等级缩放的自动修正：`tv_engineering_department_wonder_mechanics_auto_modifiers.txt`。

上述奖励本身不改变舰队寻路；真实通航状态由新增 `set_canal_open` 调用处理，实际路径仍待游戏内验收。

## 已实现的生命周期与生成归属

`scripts_engineering_department/wonder_mechanics/_core.py` 校验 `native_canal` 为 boolean，并在标准化数据中保留。仅苏伊士启用此字段，其他奇观不改变通航状态。编辑器写回保留源数据中的其他字段。

### 完成与重建

`gen_tv_wonder_finalization_effects.py` 在已有一天延迟的实际最终建筑完成同步回调中，确认当前地点为 `location:suez` 且任一最终建筑完成等级至少为 1 后执行 `set_canal_open = yes`，再刷新地点显示。新建、升级和重建沿用同一确认入口。中间模块、仪式预览和开始施工不会开放。

延迟读取实际完成等级，避免在引擎尚未提交等级时用 `has_building` 或同 tick 读取代替完成判断。生成输出为 `tv_wonder_finalization_effects.txt`，归属登记在 `data/generated_files.yaml`，不手改产物。

### 拆除

共享 mechanics 生成器的 `append_final_building_destruction_effects` 在已有每个奇观的一天延迟拆除位置回调中，同步实际等级后，确认 `this = location:suez` 且没有任一最终建筑完成等级至少为 1，才执行 `set_canal_open = no`。保留至少一级时不关闭。关闭在 `owner ?= { ... }` 之前执行，因此地点没有 owner 也能关闭；其后继续既有奇观优先施工、奖励和所有权处理。

该逻辑由 `gen_tv_wonder_location_display_effects.py` 调用并写入 `tv_wonder_location_display_effects.txt`。只运行主 mechanics effect 生成器不会更新这份拆除输出。

### 原版共存和状态边界

原版决议与 TV 奇观共存。TV 不调用 `start_canal_construction`，不会因自己的开始施工再开启一套原生计时和成本；玩家仍可分别选择两条路径。原版过去建成不优先于 TV 最后一级拆除，关闭后原版后续完工可以重新开放。此时运河可在没有 TV 建筑时保持开放，直到下一次适用的 TV 拆除回调改变它。

不记录建成来源，不增加月度强制同步、所有权转移关闭、读档重建或旧状态迁移。存档依赖引擎保存运河状态和现有排队事件。原版完工与 TV 延迟拆除发生在同日时的执行顺序必须游戏内确认。

### 固定地点

当前奇观与原生地图 through-location 都固定为 `suez`。仅移动奇观地点不能迁移原生通路；未来更改必须同步地图邻接并验证目标引擎支持。

## 风险与边界

- 当前证据来自本工作区的 EU5 1.4 beta 参考文件，不等同于最终正式版。
- Canal Manager 的核心可通行判定在 C++ 中，脚本只能调用公开状态和效果接口，不能重写其关系判断。
- `canal` 邻接属于地图数据；没有对应邻接时，`set_canal_open` 不能凭空创建跨海通路。
- 奇观的经济、贸易、地点发展和仪式奖励仍属于 Towards Victory 逻辑，原生运河只替代真实通行状态。
- 当前已完成代码接入和静态验收，实际通航、战争限制、原版共存及保存／加载仍未实测；静态通过不能代替游戏内验收。
