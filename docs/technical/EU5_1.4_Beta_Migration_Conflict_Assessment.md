官方变更明确移除了 country-scope on_action `on_colonial_charter_finished`（`changes_script_docs.md:683-684`）。项目仍在以下运行时链路中使用它：

- `data/task_pool.yaml:292-296` 的 `complete_colonial_charter` 任务依赖该 hook；

- `data/index/scripted_effects.txt:463`、`486` 仍保留对应的生成索引项；这些索引必须在源数据修复后统一重生成。

1.4 reference 中没有同名完成回调，只有 `colonial_charter_monthly.txt` 和 `on_colonial_charter_failed` 等不同语义的入口。不能保留旧名字的 wrapper，也不能把失败回调当作完成回调。

### P2：新增体系是迁移机会，不是当前阻塞

1.4 新增 expedition/ambition/religious order/calling/industry promotion 等 scope/type，以及 IO 的 `embargo`、`assists_in_rebellions`、`assists_in_civil_wars`，和平条约 `apply_antagonism`、subject `ai_biases`、town rights specialization/upgrades、unit type culture/religion 强制项等。当前项目没有直接依赖这些新 API，也没有 `ai_will_select` 旧名称命中；因此不应为了“跟上版本”在本次迁移中批量改造。

后续功能开发可按模块逐项采用，并先读取对应 1.4 type/script docs。若未来引入 resolution 等新 schema，使用 `ai_will_propose`（旧 `ai_will_select` 的改名）和当前 1.4 的 `ai_vote_weight`/`validate_vote_trigger`。

## 生成与迁移顺序

按以下顺序执行，避免生成器读取半迁移状态：

1. **冻结并扫描**：记录 `git status`；运行 `scripts/ai_context.py --changed`；保存旧 API 命中清单。
2. **先修数据源**：处理 `data/pulse_registry.yaml`、`data/philosophy_debates.yaml`、`data/task_pool.yaml`、`data/cost_reward_units.yaml`；不编辑生成输出。
3. **重生成 feature outputs**：辩论效果/事件/本地化、任务输出、pulse bridges、wonder editor catalog。
4. **同步 vanilla full copies**：运行 `gen_character_title.py`、`gen_messagetypes.py`；处理 Eureka 无 owner 副本；手工 rebase `encyclopedia_lateralview.gui`，重新生成并审计 `location_window.gui` 和 `siphon_income.txt`。
5. **接入 Suez**：更新奇观数据/生成器，再生成最终化效果；检查只在最终完成分支调用 `set_canal_open`。
6. **刷新索引**：运行 `scripts/gen_index.py`，最后才检查 `data/index/*`。
7. **全局静态扫描**：确认被删除 hook、modifier、scope 和旧 script value 不再出现在可加载项目源文件中；普通本地化文本和生成索引的变化按来源解释。
