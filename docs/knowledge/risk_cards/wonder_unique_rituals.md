# Unique Wonder Rituals Risk Card

Load this card before implementing or reworking bespoke unique-wonder rituals.

## Current State

- Only Pharos Lighthouse and Hagia Sophia have loadable bespoke unique-ritual
  source.
- Other unique wonders keep design/spec records but use the generic immediate
  ceremony path unless explicitly reimplemented.
- Bespoke implementation is hand-written per wonder under
  `scripts_engineering_department/unique_wonder_ritual_content/` and generated by
  `scripts_engineering_department/gen_unique_wonder_rituals.py`.

## Required Checks

1. Do not reuse another wonder's mechanic template.
   Similar high-level sequences count as homogenization even when literal code
   differs. Keep mechanics specific to the historical wonder.

2. Read the design source first.
   Use `data/unique_wonder_ritual_specs.yaml`, localization data, and the current
   content module for the individual wonder. Do not infer a shared engine from
   other wonders.

3. Verify on_action war scopes when a ritual reacts to war.
   Use exposed `scope:winner` / `scope:loser` checks, not merely "a war ended".

4. Keep runtime-variable cleanup current.
   After renaming ritual variables in a content module, regenerate the shared
   ritual cleanup effects so old names are not removed while new names leak.

5. Keep event text dictionaries structured.
   Option letters must live under an `options` sub-dict; do not let option letter
   keys collide with title/description keys.

6. Audit uniqueness after implementation.
   Similarity checks are mandatory after adding or reworking a bespoke ritual.
