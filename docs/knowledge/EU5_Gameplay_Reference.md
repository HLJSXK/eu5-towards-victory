# EU5 玩法参考：Towards Victory application notes

Read `.eu5-base/docs/knowledge/EU5_Gameplay_Reference.md` first.

## 14. 怎样把玩法知识用于本项目

### 14.1 六条胜利路径各自承接什么自然行为

| 路径 | 可承接的自然行为 | 设计时必须考虑 |
|---|---|---|
| 征服 | 选战略目标、赢得战争、建立可治理领土 | 战争准备、停战恢复、人口损失、整合、敌对感；不能只数地点 |
| 繁荣 | 稳定经营、就业、粮食、基础设施与增长 | 总量与人均、人口规模差异、实际运行和长期可持续性 |
| 贸易 | 市场参与、运力、供给、航线和专业化 | 贸易利润与国家税收区别、市场外部冲击、战略亏损贸易 |
| 外交 | 关系、人情、继承、属国、组织与和平整合 | 行动合法性、容量、忠诚、随机继承；不能把属国当直辖 |
| 文化 | 语言、识字、文化传播、社会治理与作品 | 接受与同化区别、人口差异、地方与全国效果范围 |
| 科学 | 制度传播接纳、研究、教育与采用新技术 | 解锁与速度区别、国家独有内容、不能只奖励建筑数量 |

这些是任务设计方向，不声称当前六条路径已经实现所有指标。落地前读取 `data/victory_paths.yaml` 及相关任务源，不按本文自行改写项目现有规则。

### 14.2 奇观与职位应改善一个可解释的瓶颈

例：水利项目可以改善粮食与人口承载，港口网络可以支持海上连接与贸易，学术项目可以支持识字和科研条件，行政中心可以支持治理。要说清地方与全国作用、建设／运营所需人口和商品、持续成本及替代投资，不能只把历史名称配给任意一组全国增益。

评估奖励时至少比较三个机会成本：相同资金可造什么；相同人口可做什么；相同人物／内阁时间可执行什么行动。一个强大奖励若同时免费提供原料、劳力、治理和科研，可能抹掉多条玩法路线之间的取舍。

### 14.3 为任务编写“玩法说明卡”

每个新任务／机制在写脚本之前，先用以下格式写出设计理由：

```text
目标玩家与阶段：国家/地区/时代/和平或战争/原版或TV内容
当前局面：人口、财政、行政、市场、外交与知识条件
真实瓶颈：为什么现有系统不能轻易完成目标
玩家行动：在哪里、做什么、需要哪些前置条件
成本：钱、商品、人口/人力、内阁时间、政治影响力、外交代价
预期结果：解锁、产出、控制、贸易或政治状态怎样改变
失败条件：缺投入、敌人干预、市场重划、人口损失等
替代路线：是否允许另一种符合目标的正常玩法
证据与版本：来源ID+原版key；哪些仅为预览或玩家经验
验收：检查已建成/已就业/已产出/已持续多久中的哪一种
```

不要把实现方便当作玩法成立。例如“拥有五座建筑”可以检查，但不能证明五座建筑满员、投入充足或发挥了历史功能；“每月收益为正”也不能证明不是靠铸币与暂时补贴维持。

## 15. 后续 AI 的查证规则与常见误用

1. **先说明当前局面，再给动作。** 不在不知道国家、时代和市场的情况下给确定开局。
2. **先找实际瓶颈，再给修正。** 缺工、缺投入、低控制、低可及性是不同问题。
3. **分清数据层。** 资源潜力、建成等级、实际就业、生产效率、产量、利润、税基和税收不得互换。
4. **分清政治与文化状态。** 征服、整合、核心、接受文化、同化和转教分别核对。
5. **分清钱与资源。** 有钱不保证有建材、船员、工人、政治影响力或可用内阁席位。
6. **不照搬 EU4。** 不假设固定贸易流、点数造核、固定团人数或固定步骑炮比例。
7. **不复制旧 bug 路线。** Z04 灾难顺序、旧版特殊吞并或降维护技巧须重新验证。
8. **不把开发日志当现行实测。** 1.4 预览、DLC 内容与本地可用功能分层记录。
9. **不凭页面更新时间定版。** Wiki 新修订可能仍有 pre-release／rewrite 标记。
10. **不凭视频标题生成操作。** 未观看或无可审阅字幕的资料保持待研究状态。
11. **不把文件存在当引擎行为已证实。** tooltip、定义、脚本效果与实际结算可能不同；重要数值需运行验证。
12. **保留证据链。** 新结论写明来源、版本、条件；若与本文冲突，更新主文与阅读记录，勿不断叠加相互矛盾的建议。

- 引擎内部税收、商品分配、市场可及性和战斗公式；只有概念说明时不补造精确公式。
- 各补丁与 DLC 的最终发布内容。重要机制以本地当前数据和实际启用内容复核，开发方案可能更改。

更新时把新知识归入对应系统与案例；优先解决冲突、补齐适用条件，不把本文变成版本日志或纯来源目录。
