# Towards Victory — Project Overview

## Mod Identity

- **Mod Name:** Towards Victory (胜利条件)
- **Mod ID:** `eu5mp.towards_victory`
- **Version:** 0.1.0
- **Target:** EU5 `1.*.*`
- **Status:** In Development — All 6 Victory paths fully implemented: Conquest, Prosperity, Trade, Diplomatic, Cultural, and Scientific
- **Language:** English + Simplified Chinese

## Summary

Towards Victory adds 6 generalized victory paths to EU5: Conquest, Prosperity, Trade, Diplomatic, Cultural, and Scientific. Each path has 5 milestone nodes that grant permanent buffs when reached. Progress is displayed via situation panels; milestones trigger popup events that notify the player and deliver the reward.

The **Conquest Victory** path (征服胜利) is fully implemented: 5 triggers, 5 reward modifiers, 5 events, and localization in English and Simplified Chinese. Score = direct locations + 0.5 × subject-or-below locations; thresholds at 200 / 400 / 600 / 1200 / 2500.

The **Prosperity Victory** path (繁荣胜利) is fully implemented: 5 triggers, 5 reward modifiers, 5 events, and localization in English and Simplified Chinese. Score = (total_population + Σdev + country_tax_base) × 50 / (N + 50) × (1 + stability/100) × (gov_power/100), where N = num_owned_locations and gov_power = legitimacy/republican_tradition/devotion/tribal_cohesion/horde_unity by government type. The 50N/(N+50) effective scale term provides stronger diminishing returns on country size. Updated yearly; thresholds at 2,000 / 3,000 / 5,000 / 7,000 / 11,000 (provisional, calibrate after playtesting).

**Prosperity main-mechanic foundation:** Prosperity M1 now creates the **Engineering Department IO** (`tv_engineering_department`), a non-unique founder-only IO with no parliament tab and no automatic leader election. Its appointed character leader is the **Great Engineer**, stored on the leader country as `tv_great_engineer_char` and managed by generated Appoint/Remove/Change leader actions. The IO currently defines skeleton variables for future wonder construction: `tv_wonder_domestic_support` (0-200), `tv_wonder_survey_progress` (0-100), and `tv_wonder_materials_stockpile` (0-300000). The custom IO panel has an overview status card, header-based Great Engineer appointment/replacement/dismissal controls, and a non-functional Wonder Construction UI covering the future stages from `docs/design/Original_Design.md`: conception and debate proposal controls, upper-estate demand rows, survey progress and competence readouts, organization/logistics progress bars, construction-unit rows, and ceremony style/effect previews. These UI controls are placeholders only and do not yet execute gameplay logic.

The **Trade Victory** path (贸易胜利) is fully implemented: 5 triggers, 5 reward modifiers, 5 events, and localization in English and Simplified Chinese. Score = monthly_trade_income (snapshot taken monthly by tv_update_trade_score_effect); thresholds at 100 / 200 / 400 / 1000 / 2000 (provisional, calibrate after playtesting).

The **Diplomatic Victory** path (外交胜利) is fully implemented: 5 triggers, 5 reward modifiers, 5 events, and localization in English and Simplified Chinese. Score = `tv_diplomatic_victory_points` accumulated permanently via `on_royal_marriage` (+3 DVP per party) and `on_winning_war` (+5 DVP to winner); thresholds at 50 / 120 / 220 / 380 / 580 (provisional, calibrate after playtesting). **Diplomatic Alliance IO** (`tv_diplomatic_alliance`): non-unique IO using the same character-leader-with-appointment pattern as the Arts Exhibition and Academy of Sciences IOs (`tv_diplomatic_alliance_leader_char` country variable; `leader_change_trigger_type = none`; leader titled Advocator). This IO has a custom `organization_panel` with HRE-style header (tier piechart at 220,60; cohesion piechart at 294,60; leader country flag), a parliament tab (`tv_alliance_assembly` parliament type, `uses_parliament_for_law_votes = yes`) for the 5-law system, and two IO-native variables: `tv_alliance_tier` (max 15, incremented by law reforms) and `tv_alliance_cohesion` (max 100, `monthly_change` driven by base +0.1 and `leader_country.modifier:diplomatic_reputation × 0.05`).

The **Cultural Victory** path (文化胜利) is fully implemented with an Arts Exhibition layer: 5 triggers, 5 reward modifiers, 5 events, and localization in English and Simplified Chinese. Score = `tv_cultural_influence_points` (CIP) accumulated via `on_work_of_art_created` (+3 CIP, scope `root.owner`) and `monthly_country_pulse` (+1 CIP per month); thresholds at 50 / 200 / 400 / 800 / 1600. M2–M5 also require `tv_arts_intl_influence` ≥ 25 / 50 / 75 / 100 respectively. **Arts Exhibition IO** (`tv_arts_exhibition`): non-unique IO; each country creates its own instance at M1 via `create_international_organization` with `set_leader_country = prev`. `tv_arts_intl_influence` (International Influence) is an **IO type variable** (`variables = { }` block) with `min = 0 / max = 100 / start = 0`, automatic `monthly_change` decay of −0.05/month (shown in the IO panel's standard `ios_information_header` piechart with `IOVariableTooltip` monthly breakdown). All effect sites modify it via `every_international_organizations_member_of = { limit = { international_organization_type = international_organization_type:tv_arts_exhibition } change_variable = { ... } }`. M2–M5 milestone triggers use `any_international_organizations_member_of = { ... var:tv_arts_intl_influence >= N }` from country scope. **IO leader = a court artist** (`leader_type = character`, manually appointed via Appoint/Remove/Change Leader actions in `tv_io_leader_actions.txt`; leader character stored on leader_country as `tv_arts_exhibition_leader_char`; IO `leader = { leader_country ?= { var:tv_arts_exhibition_leader_char ?= { add_to_list = leaders } } }` with `leader_change_trigger_type = none`). The appointed leader's `artist_skill × 0.002` is added to `tv_arts_intl_influence.monthly_change` (via `leader_country.var:tv_arts_exhibition_leader_char.artist_skill` chained access). Three further generic actions: "Send Artist Abroad" (200 ducats, 3-step selection: artist → country → location; 1–10 year tour with `yearly_country_pulse` timer and `on_character_death` hook), "Host Domestic Exhibition" (1000 ducats, +0.1 per owned artwork). The IO panel header shows the leader character automatically (standard vanilla character-leader IO header); no custom portrait slot is needed. **Standard touring events** (~8% per artist per month, skill-weighted): unremarkable (+0.1), great success (+0.5), terrible (−0.1), artist hired (+1.0 permanently), artistic inspiration (+10% artist_skill_level_gain for 10 years). Character modifier: `tv_artistic_inspiration_modifier`. **5 parallel monthly special events** (1/300 per artist per month each, once-per-tour guard `tv_tour_event_1_fired`–`tv_tour_event_5_fired`): 201 Cultural Diplomacy (bilateral +20 opinion `tv_cultural_diplomacy_opinion`, `yearly_decay = 6`), 202 Exhibition Success (5-year `tv_exhibition_success_location_modifier` on location: `local_migration_attraction +2`, `local_unrest −0.2`, `local_production_efficiency −0.2`), 203 Noble Patron (construct theater at exhibition location free, `cost_multiplier = 0 instant = yes`), 204 Artist Exchange (both touring artist and a local artist gain permanent `add_artist_skill = 0.05`), 205 Art Theft + Artist Death (destroy host artwork via `destroy_art`, −20 permanent opinion `tv_art_theft_opinion`, dispatch state cleaned up, `tv_on_exhibition` removed before `kill_character = this` to suppress double `.6` death event). **Probabilistic return** via `tv_end_artist_exhibition_effect`: 90% plain return event (.5); 2% × 5 special outcomes: .120 artwork brought home (`move_art + set_art_owner`), .121 inspiration creates art (`create_art`), .122 research progress (`add_research_progress = research_progress_mild_bonus`), .123 artist retires (`kill_character = this`), .124 gold donation (random 50–150 ducats). `scope:exhibition_target` is saved at the top of `tv_end_artist_exhibition_effect` for use in return event option effects. All tour-end paths (return effect, `on_character_death`, Artist Hired branch, event 205) clean up the 5 once-per-tour flag variables. **Dispatch constraints:** Each dispatched artist reduces the home country's `num_possible_artists` cap by 1 via a pre-defined country modifier (`tv_touring_penalty_N`, where N = current dispatch count; managed by `tv_update_tour_capacity_effect`). The home country tracks the count in `tv_dispatched_artists_count` (initialized to 0 in IO `on_creation`, updated on dispatch/return/death). A marker variable `tv_has_visiting_artist` is set on the target country when an artist arrives and cleared when they return or die; Step 2 of the dispatch selection filters out countries that already carry this marker so at most one artist from any IO member can tour each country at a time. The IO panel displays the current dispatched count via a `TV_ARTS_DISPATCHED_COUNT_LABEL` / `GetValue|0` widget.

**Current local exhibition mechanic:** The old one-click domestic exhibition has been replaced by a persistent local exhibition system. `tv_host_domestic_exhibition` requires at least 5 owned artworks, costs `scaled_gold = 3.5`, and uses a location select trigger. The chosen location receives the event-only `tv_local_arts_exhibition` building (nobles, employment 0.05, cultural category, heavy art-goods maintenance, `local_migration_attraction = 2`, `local_production_efficiency = -0.2`, `local_unrest = -0.2`), is stored as `tv_local_exhibition_primary_location`, and is added to the `tv_local_exhibition_locations` variable list. The IO variable `tv_local_exhibition_enthusiasm` starts at 80, caps at 200, decays by 8/month while active, and ends the exhibition at 0; the country tracks active state, active location list/count, committed exhibits, duration, rating, and a 12-month post-exhibition cooldown. The player expands the exhibition with `tv_local_exhibition_expand` (`scaled_gold = 1.0`, no cooldown): the next exhibit tranche is committed using the old escalating requirements (5, then 10, then 20), the player selects an owned location adjacent to any active exhibition location, the special building is constructed there, the location is added to `tv_local_exhibition_locations`, and +10 Enthusiasm is awarded. Closing rewards are per-location CIP multiplied by `tv_local_exhibition_location_count`: per-location CIP = 0.5 × duration in months + tier bonus, with tier bonuses at ratings 1/2/3/4 = -3 / 0 / +3 / +6. Prestige rewards are not multiplied: tier 1 loses 10 Prestige, tier 3 adds +10 Prestige, and tier 4 adds +15 Prestige. Tier 4 still grants +0.25 development and +0.1 prosperity to the primary location, while the 1-year `tv_local_exhibition_triumph_location_modifier` is applied to every location in the closing `tv_local_exhibition_last_locations` snapshot. The Arts Exhibition panel's custom tab shows owned artworks, committed exhibits, active venue count, months open, rating, and a cold-to-hot enthusiasm progress bar. Active exhibitions also unlock royal visit, radical art, royal art sale, artist recruitment, foreign guest artist invitation, centerpiece designation, and live creation contest. Monthly exchange events each have a 1% chance and trade gold, Prestige, estate satisfaction, stability, legitimacy, host development, or host prosperity for +10 enthusiasm, with a decline option for -5 enthusiasm.

**Arts Exhibition laws:** The IO uses the vanilla IO Laws tab with eight generated law groups under `tv_arts_exhibition_laws`: Artistic Patronage, Artistic Organization, Official Artistic Purpose, Censorship and Artistic Freedom, Architecture and Urban Aesthetics, Knowledge Transmission Media, State Ritual Aesthetics, and Relationship Between Art and Science. All laws use `requires_vote = yes`, `has_parliament = no` hides the separate IO Parliament tab, and `on_creation` seeds the default policies: Church Patronage, Guild System, Glory of God, Strict Censorship, Utilitarianism, Manuscripts and Frescoes, Plain Ritual, and Craft Tradition. Each policy carries 1-2 positive and 1-2 negative country modifiers, with strength kept near a single Advance or estate privilege.

**Arts exchange mechanic:** The Arts Exhibition IO shows the arts exchange information and action cards in the resolutions tab, leaving the overview tab for touring controls and the vanilla Laws tab for legal policy votes. A country can start a year-long exchange with `tv_start_arts_exchange` (`scaled_gold = 2.0`) when it has an appointed Chief Artist and at least two living artists; there is no cooldown, but an active exchange blocks starting another. The country tracks `tv_arts_exchange_active`, elapsed/remaining month variables, and persistent participant lists (`tv_arts_exchange_participants`, `tv_arts_exchange_foreign_participants`), while each participant receives marker variables for cleanup and selection filtering. When the exchange starts, the country immediately preselects up to three additional domestic artists, stores them in `tv_arts_exchange_auto_invite_1/2/3`, shows them in event `tv_arts_exhibition.400`, and applies them from the event option. During the exchange the player can manually invite more domestic artists (`scaled_gold = 1.0`) or foreign artists (`scaled_gold = 1.5`, country selection then character selection); all invite selectors exclude artists currently touring abroad, local exhibition guest artists, and existing exchange participants. Monthly exchange outcomes fire through events with a 50% monthly roll and equal event weights among eligible outcomes: artist skill gains/losses, high-skill artist teaching, foreign praise for Prestige, masterpiece creation, +5 CIP, a random new folk artist, ruler DIP gain, or a no-effect dispute. `tv_arts_exhibition.420` announces the end and clears all exchange state.

Chief Artist work is mutually exclusive: Arts Exhibition law-change policy votes, Arts Exchange hosting, and Domestic Exhibition hosting each block the other two, with explicit busy-state tooltip text naming the active task.

**Arts influence clarification:** `tv_arts_intl_influence` decays by 0.1% of its current value per month and is still driven primarily by foreign artist tours and the appointed Chief Artist. Persistent local exhibitions award `tv_cultural_influence_points` at closure rather than directly adding International Influence.

The **Scientific Victory** path (科技胜利) is fully implemented with a unique Academy of Sciences building gate: 5 triggers, 5 reward modifiers, 5 events, and localization in English and Simplified Chinese. Score = `num_of_advances_researched` (snapshot taken monthly by tv_update_science_score_effect); thresholds at 100 / 150 / 200 / 300 / 400 (provisional, calibrate after playtesting). Rewards: M1 research speed, M2 institution spread/discipline, M3 institution spread/pop growth, M4 institution embrace cost/production, M5 production/discipline. **Unique mechanic:** Each milestone only fires after the corresponding **Academy of Sciences** building phase is manually constructed in the capital. The building chain (Phases I–V) is visible from game start; each phase requires the previous phase plus the corresponding score threshold (`tv_academy_of_sciences_level` variable). Construction conditions use `custom_tooltip` (score variable is not auto-parseable). **Academy of Sciences IO** (`tv_academy_of_sciences`): non-unique IO created by the Scientific Victory M1 reward after Phase I (`tv_academy_of_sciences_1`) is built; the same M1 popup both announces the Academy and grants the milestone reward. The reward sets `tv_academy_io_member = 1`, initializes research mechanism variables, and calls `create_international_organization`. **IO leader = an appointed non-artist character** (Chief Scientist), set manually via Appoint/Remove/Change Leader actions in `tv_io_leader_actions.txt`; leader character stored on leader_country as `tv_academy_leader_char`; IO `leader = { leader_country ?= { var:tv_academy_leader_char ?= { add_to_list = leaders } } }` with `leader_change_trigger_type = none`. The IO uses the vanilla IO Laws tab for `tv_science_factions` and `tv_academy_leadership`: the seven Academy laws have law icons and default policies seeded at creation; six carry country_modifier gameplay effects, while `tv_academy_leader_gender_law` controls whether the Chief Scientist selector is male-only (default) or unrestricted. All keep `requires_vote = yes` for IO policy votes; the Academy sets `has_parliament = no`, hiding the vanilla IO Parliament tab. **Research Mechanism (frontier-tech shortcut):** Four sub-processes complete one full cycle, which auto-researches one chosen Frontier advance via `research_advance = advance_type:X` (these advances remain normally researchable via the vanilla research tab — the Research Mechanism is an *extra* unlock route, not a gate). Sub-process A (Interest Collection): monthly random event (`tv_research.1`, ~10% base chance) costs dynamic gold via `change_gold_effect = { scale = -2 }` and adds +1 to `tv_research_interest`; completes at 5. Sub-process B (Prerequisites): institution-root targets require at least one owned location matching the corresponding institution's plausible spawn conditions with geography/region gates removed; non-institution-root targets still complete automatically. Sub-process C (Literacy Foundation): **IO variable** `tv_research_c_progress` accumulates `average_country_literacy × 0.05` per month; completes at 100 (~40 months at 50% literacy). When A/B/C are all complete, `tv_research.19` fires a one-time no-effect reminder that concentrated research can now begin. Sub-process D (Concentrated Research): **IO variable** `tv_research_d_progress` accumulates `effective ADM × 0.05` per month (base `leader_country.var:tv_academy_leader_char.adm` plus +20/+40/+60 from `tv_great_scientist_1/2/3`); completes at 100 based on effective ADM and then grants or upgrades the current Chief Scientist's Great Scientist trait. D halts when no leader appointed; while active it also applies `tv_concentrated_research_penalty` (−20% research speed), removed silently on completion or reset. **Target selection:** Player clicks "Request Research Topic" → strict-earliest-age random proposal (each candidate is excluded if `has_advance = vanilla_id` is true OR if any earlier-age Frontier advance is still unresearched) → event `tv_research.10` for confirmation; abandoned targets set 12-month cooldown. **20 active Frontier advances:** 1=printing_press_advance(A3), 2=iron_working(A1), 4=gunpowder_advance(A2), 5=blast_furnace(A3), 6=scientific_experimentation(A4), 7=scientific_revolution_advance(A5), 8=manufactories_advance(A5), 9=industrialization_advance(A6), 10=vaccination_advance(A6), 11=renaissance_advance(A2), 12=banking_advance(A2), 13=professional_armies_advance(A2), 14=new_world_advance(A3), 15=pike_and_shot_advance(A3), 16=confessionalism_advance(A4), 17=global_trade_advance(A4), 18=artillery_institution_advance(A4), 19=military_revolution_advance(A5), 20=enlightenment_advance(A6), 21=levee_en_masse_advance(A6). Value 3 is retired from the old anatomy_advance(A2) target and is intentionally not reused. Each is listed in `data/locked_advances.yaml`; `tv_unlock_advance_<id>_effect` is generated by `scripts/gen_locked_advances.py` and called by `tv_research_concentrated_complete_effect` on cycle D completion. **Cycle phases:** 0=idle, 1=A/B/C running, 2=D concentrated research. State variables: `tv_research_phase`, `tv_research_target`, `tv_research_interest`, `tv_research_b_done`, `tv_research_selection_cd`; display vars: `tv_rm_subprocess_a/b/c`, `tv_rm_subprocess_d_ready`. IO panel (`tv_academy_of_sciences.gui`) keeps the overview focused on target, CD, Chief Scientist name (from appointed character), subprocess A/B/C/D status, current B requirements rendered with `RequirementsList` + `ShowTriggerConditions('tv_research_check_b_trigger', PlayerScope.Self)`, and three research action buttons. A dedicated Chief Scientist tab shows the variable-backed character card or vacancy state and contains the Appoint/Change/Remove leader actions in its Action Card; when a leader is appointed, it also shows an effects card with base Administrative Skill, base Concentrated Research speed, and base Monthly Cure Progress. The victory situation panel keeps Scientific Victory to the shared progress row; Academy operational details live in the IO panel. **Medicine Tab:** A separate Medicine tab in the IO panel lets the player treat a court character with a bad health trait. The player clicks "Treat Character" (`tv_treat_character` generic action) to pick a target filtered by `tv_has_health_condition_trigger` (blind, one_eyed, maimed, disfigured, scarred, hunchback, pockmarked_trait, smallpox_trait, bubonic_plague_trait, sickly). Once a patient is selected, `tv_med_target_char` (country variable on leader_country) holds the character reference; only one active patient at a time. Monthly processing (in `monthly_country_pulse` effect block): if the Chief Scientist is alive, cache effective ADM into `tv_med_disp_adm` and base `dip/mil` into `tv_med_disp_dip/mil` for display, then `tv_med_progress += effective ADM × 0.1`; when progress ≥ 100, `tv_med_complete_treatment_effect` fires (`tv_medicine.3` popup, all bad health traits removed, state reset). Patient natural death triggers `tv_medicine.4` popup and state reset. Sub-action `tv_med_discovery_pulse` fires `tv_medicine.1` (~1%/month, fixed approximation of dip×0.2%): three options — Conservative (95%: +5 progress / 5%: patient dies), Risky (80%: +10 progress / 20%: patient dies), Wait (no effect). Sub-action `tv_med_accident_pulse` fires `tv_medicine.2` (~5%/month, fixed): notification only. Tab displays: current patient name (or "None"), progress bar (max 100, visible when patient active), monthly gain rate, discovery chance, accident chance. State variables: `tv_med_target_char`, `tv_med_progress`, `tv_med_disp_adm`, `tv_med_disp_dip`, `tv_med_disp_mil` — all country variables on leader_country, initialized in `tv_academy.1` join event and reset by `tv_med_cleanup_effect`.

Chief Scientist work is mutually exclusive: concentrated research, Academy law-change policy votes, and medical treatment each block the other two, with explicit busy-state tooltip text naming the active task.

Current concentrated research behavior: D progress and completion require a living Chief Scientist with at least 20 effective ADM. The player can pause D with `tv_pause_concentrated_research`, preserving `tv_research_d_progress` while freeing the Chief Scientist for laws or medicine. While D is active, `tv_research_d_pulse` uses one shared `random_events` list for `tv_research.100`-`.129`; each currently eligible event has 1% monthly weight, and eligibility is gated by effective ADM tiers <20, 20-49, 50-79, and >=80.

Great Scientist traits (`tv_great_scientist_1/2/3`) are Chief Scientist-only character traits in `src/in_game/common/traits/tv_great_scientist_traits.txt`. They add +20 / +40 / +60 effective ADM only while the character is appointed as the Academy Chief Scientist; they are read by concentrated research progress, D-event tiering, and Medicine monthly progress. Completing concentrated research grants the current Chief Scientist level 1 or upgrades level 1→2→3; level 3 stays capped.

The mod is additive-only and uses the `tv_` namespace prefix throughout.

## Core Features

1. **6 Victory Situations** — One situation (`tv_victory_situation`) displays all 6 victory paths in a single panel with a top-level manual recovery button (`tv_reinitialize_mod`), a flavor text introduction (Section 1), per-path progress bars and milestone circles (Section 2), and a global leaderboard (Section 3).
2. **Milestone Events** — Popup country events per milestone. All 30 events implemented across 6 paths: Conquest (`tv.conquest.1`–`5`), Prosperity (`tv.prosperity.1`–`5`), Trade (`tv.trade.1`–`5`), Diplomatic (`tv.diplomatic.1`–`5`), Cultural (`tv.cultural.1`–`5`), and Scientific (`tv.science.1`–`5`).
3. **Permanent Rewards** — All 30 milestone rewards are permanent static modifiers (`days = -1`); no time-limited buffs. All 6 paths fully implemented.
4. **Diplomatic Victory Points** (`tv_diplomatic_victory_points`) — Permanently accumulated via `on_royal_marriage` (+3 DVP each party) and `on_winning_war` (+5 DVP to winner).
5. **Cultural Influence Points** (`tv_cultural_influence_points`) — Accumulated via `on_work_of_art_created` (+3 CIP to `root.owner`), `monthly_country_pulse` (+1 CIP/month), and persistent local exhibition rewards from the Arts Exhibition IO.
6. **Scientific Technology Score** (`tv_science_score`) — Monthly snapshot of `num_of_advances_researched`; thresholds 100 / 150 / 200 / 300 / 400.
7. **Academy of Sciences Building Chain** — Five capital buildings (`tv_academy_of_sciences_1`–`5`) gate Scientific Victory milestones. Each requires the previous phase built and the corresponding score threshold; `on_built` immediately triggers `tv_check_science_milestones_effect`. Building category: `cultural_category`; visible in all capitals from game start. Phase I no longer fires a separate Academy popup; Scientific Victory M1 creates the **Academy of Sciences IO** (`tv_academy_of_sciences`) inside its reward effect and shows a custom tooltip pointing to the Research Mechanism in the International Organization interface. Membership flag: `tv_academy_io_member` (country variable set to 1 on join). IO leader (Chief Scientist) = appointed non-artist character stored on leader_country as `tv_academy_leader_char`; managed via the Appoint/Remove/Change Leader actions in `tv_io_leader_actions.txt`. `leader_change_trigger_type = none`; `international_organization_chooses_new_leader` is deliberately NOT called — it triggers the vanilla leader-election process, violating the no-elections design. The Academy has a vanilla IO Laws tab but no Parliament tab; `tv_science_factions` and `tv_academy_leadership` law changes keep `requires_vote = yes`. `tv_academy_leader_gender_law` defaults to male-only and removes the female-candidate filter only under `tv_academy_leader_gender_unrestricted_policy`.
8. **Research Mechanism (Frontier-Tech Shortcut)** — Full four-subprocess cycle that auto-researches one of 20 active Frontier advances via `research_advance` on cycle completion. The advances remain normally researchable via the vanilla tech tree — the Research Mechanism is an *extra* unlock path, not a gate. Sub-process A: monthly random interest events (~10%; 5 funded successes needed; event namespace `tv_research`; each success costs dynamic gold via `change_gold_effect = { scale = -2 }`). Sub-process B: passive prerequisite check; institution-root targets require at least one owned location matching the corresponding institution's plausible spawn conditions with geography/region gates removed, while non-institution-root targets still complete automatically. Sub-process C: IO variable `tv_research_c_progress` auto-accumulates via `monthly_change`; completed by `monthly_effect`. Once A/B/C are all complete, `tv_research.19` pops once as a no-effect reminder that concentrated research can begin. Sub-process D: IO variable `tv_research_d_progress` auto-accumulates via the appointed leader's effective ADM (base ADM plus Great Scientist trait bonus), applies `tv_concentrated_research_penalty` (−20% research speed) while active, triggers unlock on completion, and grants/upgrades that Chief Scientist's Great Scientist trait. Three research generic actions: `tv_request_research_target`, `tv_abandon_research_target`, `tv_start_concentrated_research`. Lifecycle managed by scripted effects in `tv_research_subprocess_effects.txt`; conditions in `tv_research_subprocess_triggers.txt`; the Academy overview displays B's current conditions via `ShowTriggerConditions('tv_research_check_b_trigger', PlayerScope.Self)`. **20 active Frontier advances:** 1=printing_press(A3), 2=iron_working(A1), 4=gunpowder(A2), 5=blast_furnace(A3), 6=scientific_experimentation(A4), 7=scientific_revolution(A5), 8=manufactories(A5), 9=industrialization(A6), 10=vaccination(A6), 11=renaissance(A2), 12=banking(A2), 13=professional_armies(A2), 14=new_world(A3), 15=pike_and_shot(A3), 16=confessionalism(A4), 17=global_trade(A4), 18=artillery_institution(A4), 19=military_revolution(A5), 20=enlightenment(A6), 21=levee_en_masse(A6). Value 3 is retired from the old anatomy(A2) target and is intentionally not reused. Each is listed in `data/locked_advances.yaml` with `vanilla_advance_id` and `age` fields; the `tv_unlock_advance_<id>_effect` (set_variable + `research_advance = advance_type:<vanilla_id>`) is generated by `scripts/gen_locked_advances.py`. Target proposal uses strict-earliest-age priority: each candidate is excluded if `has_advance = vanilla_id` is true OR if any earlier-age Frontier advance is still unresearched.
9. **IO Leader Management** — Unified character-leader pattern across five TV character roles (Arts Exhibition, Diplomatic Alliance, Academy of Sciences, Governor's House Grand General, Engineering Department Great Engineer). Each IO uses `leader_type = character` + `leader_change_trigger_type = none` + `leader_change_method = none` + a `leader = { leader_country ?= { var:tv_<io>_leader_char ?= { add_to_list = leaders } } }` block, with Governor's House using `tv_conquest_general_char` and Engineering Department using `tv_great_engineer_char`. Fifteen generic actions (5 roles × 3 actions) in `tv_io_leader_actions.txt`: Appoint, Remove, Change. Each action sets or clears the country variable only — `international_organization_chooses_new_leader` is deliberately NOT called (it triggers the vanilla leader-election process, violating the no-elections design). All TV IOs have `unique = no`; never use `international_organization:type_name` syntax for them — use `every_international_organizations_member_of = { limit = { international_organization_type = international_organization_type:<io_type> } ... }` instead. Arts Exhibition filters candidates by `is_artist = yes`; Academy and Engineering Department exclude artists; Diplomatic Alliance accepts any non-ruler/heir/consort alive adult character; Grand General additionally excludes female characters and artists. **Character title prefixes (Arts Exhibition + Academy + Governor's House + Engineering Department):** Appointing/removing leaders also adds/removes zero-stat character modifiers (`tv_chief_artist_role_modifier` / `tv_chief_scientist_role_modifier` / `tv_grand_general_role_modifier` / `tv_great_engineer_role_modifier`). These modifiers trigger title prefixes via generated `src/in_game/common/customizable_localization/character_title.txt` (copied from vanilla and patched by `scripts/in_game/common/customizable_localization/gen_character_title.py`) — the appointed character's name displays as "Chief Artist [Name]", "Chief Scientist [Name]", "Grand General [Name]", or "Great Engineer [Name]" (首席艺术家/首席科学家/大将军/大工程师). Modifier definitions are in `src/in_game/common/static_modifiers/tv_io_role_modifiers.txt`. The Diplomatic Alliance leader has no title modifier.
10. **Governor's House IO** (`tv_govhouse`): non-unique IO created by the Conquest Victory M1 reward (200 locations). **Governor system:** characters appointed by the player to govern EU5 regions. Bonuses scale dynamically with character attributes: `local_max_control` size = adm × 0.001 (adm 100 → +10%); `local_build_buildings_cost` size = −dip × 0.002 (dip 100 → −20%); `local_unrest` size = −mil × 0.002 (mil 100 → −20). Three governor static modifiers defined in `towards_victory_location_modifiers.txt`: `tv_governor_max_control`, `tv_governor_build_cost`, `tv_governor_unrest`. Data model: `tv_govhouse_region_list` is a persistent country variable list of region scopes rebuilt from the country's currently owned locations at IO creation and every monthly governor refresh; `tv_govhouse_region_display_list` is a parallel country variable list of representative owned location scopes used by the GUI to display one row per owned region; `tv_governor_list` remains a persistent country variable list of appointed governor character scopes. Each governor character has `tv_is_governor`, `tv_governed_region` (region scope), `tv_governed_region_capital` (representative owned location retained for compatibility), and pre-computed display variables (`tv_gov_max_control_pct`, `tv_gov_build_cost_pct`, `tv_gov_unrest_pct`). The representative display location mirrors the active governor and copied effect values via `tv_govhouse_display_governor_char`, `tv_govhouse_display_max_control_pct`, `tv_govhouse_display_build_cost_pct`, and `tv_govhouse_display_unrest_pct`. Monthly_effect in the IO calls `tv_apply_governor_bonuses_effect`, which refreshes modifiers for alive governors, prunes dead/orphaned/lost-region assignments, and then rebuilds the region/display lists; legacy `tv_governed_area` assignments are migrated/cleaned during refresh. Three region-row generic actions: `tv_appoint_governor` (UI passes `scope:target_1` region, select_trigger chooses `scope:target` character), `tv_remove_governor` (UI passes region and the effect finds the assigned governor), and `tv_change_governor` (region parameter + character selection, replacing any existing assignment); all require an alive Grand General in office. If the Grand General is dismissed or dies, existing governors remain appointed and continue refreshing, but no new governor can be appointed/changed/removed until a successor is appointed. **Grand General:** character leader stored as the independent country variable `tv_conquest_general_char`; managed via generated Appoint/Remove/Change IO leader actions and displayed in the IO header. `tv_govhouse_authority` IO variable (0-100, monthly decay × 0.0005, grows by Grand General's mil × 0.05). The Governor's House overview tab renders the display-location list: each row shows a region icon/name, right-aligned max control / construction cost / unrest effect entries with concept and formula tooltips, and the current governor as a standard `io_character_card`; Assign/Cancel/Change Governor buttons still pass the row's region scope. The dedicated Grand General tab shows the current variable-backed character, active training progress below the character card, authority value, Appoint/Change/Remove actions, and the existing Train Grand General action.

Regional Governor random events: `tv_govhouse_governor_events_monthly_pulse` runs through the generated `monthly_country_pulse` registry and only triggers if at least one living governor has an owned governed region. It uses a single monthly country-level roll with 180 no-event weight plus 20 event weights, giving a 10% total monthly chance. Events `tv_govhouse.100`-`.119` each pick one random eligible governor in `immediate`, save the governor, governed region, and a representative owned location as event scopes, then apply one-year region-wide location modifiers and/or immediate or one-year country effects. The 20-event set covers two-choice good events, one-option good events, two-choice tradeoff events, two-choice bad events, and one-option bad events.

Governor's House laws: the IO uses the vanilla IO Laws tab with six generated law groups (`tv_govhouse_expedition_goal_law`, `tv_govhouse_governor_appointment_law`, `tv_govhouse_local_autonomy_law`, `tv_govhouse_religious_mission_law`, `tv_govhouse_frontier_military_law`, `tv_govhouse_imperial_integration_law`), each with four effect-bearing policies. All six laws keep `requires_vote = yes`, `has_parliament = no` hides the separate IO Parliament tab, and `on_creation` seeds the default policies: Trade Posts, Royal Appointment, Strict Direct Rule, Secular Governance, Regular Garrison, and Permanent Colonies.

Governor's House War Tent: requires an alive Grand General. The custom War Tent tab has three units: General Tactics, War Plan, and Main Actions. On war entry, `tv_govhouse_war_entry_effect` proposes one random tactic from the seven-tactic pool and fires `tv_govhouse.40`; the player approves or rejects it. While continuously at war, the monthly pulse has a 5% chance to propose a replacement tactic, excluding the tactic already active. Approved tactics are applied as character-scoped static modifiers on the appointed Grand General, not as country modifiers, and are cleared when the country leaves all wars or loses its Grand General. War plans are mutually exclusive: offensive plans select a target country and, while at war with that target, scale Siege Ability by progress x 0.2% and Discipline by progress x 0.1%; defensive plans need no target and, while in any defensive war, scale Fort Defense by progress x 0.2% and Military Tactics by progress x 0.005. On war entry, applicable offensive/defensive plan bonuses are activated through `tv_govhouse.41` / `tv_govhouse.42` events instead of being granted directly by the war-entry effect. Plan progress increases monthly by Grand General adm x 0.02 up to 100; aborting/changing target resets it, and peace with an offensive plan target aborts that plan.

8. **Global Victory Leaderboard** — Monthly ranking of the top 5 countries by their best single-path progress (0–100 bar value). Per-country: `tv_best_path` (0–5), `tv_best_progress_pct`, `tv_best_milestone`, `tv_best_score` computed via `tv_update_best_path_effect` in `monthly_country_pulse`. Situation stores rank-1..5 country references (`tv_rank_1_country`–`tv_rank_5_country`) via `ordered_in_global_list` cascading-exclusion pattern. Displayed in Section 3 with flag, country name, leading-path circle icon, milestone count, and score text.

Governor's House eligibility/death note: new governors and Grand Generals exclude female characters and artists at the selection/action-effect entry points. There is no monthly legacy-eligibility cleanup, to keep the IO monthly path focused on active governor bonus refresh. `tv_govhouse_governor_death` is registered under `on_character_death`, fires `tv_govhouse.1`, removes the dead governor from `tv_governor_list`, clears their region modifiers, and rebuilds the display lists immediately.

Grand General training note: `tv_train_grand_general` applies the one-year `tv_grand_general_training_modifier` country modifier defined in `src/in_game/common/static_modifiers/tv_govhouse_modifiers.txt` (+10% `court_spending_cost_modifier`), tracks `tv_gg_training_months` on the Grand General via monthly pulse, mirrors it to the country-side GUI display variable `tv_gg_training_progress`, resolves at 12 months through `tv_training_resolve_effect`, and routes to skill gain, trait-path upgrade, injury, or death events before clearing state.

Grand General death notification note: natural Grand General deaths trigger `tv_govhouse.2` from `tv_govhouse_char_death`; training-caused deaths set `tv_gg_training_death_notified` before `kill_character = this` so the already-shown training death event is not duplicated.

Governor's House balance-of-power backlash note: `tv_govhouse_power_balance` is an IO variable in the 0..1 range and is checked monthly by `tv_govhouse_negative_monthly_pulse` (registered through `data/pulse_registry.yaml`). `tv_govhouse_power_equilibrium` recalculates monthly from a -10% base, the Grand General's share of combined ruler/general abilities, and `tv_govhouse_power_consolidation`; `tv_govhouse_power_balance` then moves toward that equilibrium by up to 1% per month. Below 25% no backlash events fire. At 25%/50%/75% the pulse uses a single `random_list` roll with a 300 total weight so at most one backlash event can appear per month, and each eligible event has weight 1/300. Events `tv_govhouse.10`-`.13` are tier 1, `.20`-`.25` are tier 2, and `.30`-`.34` are tier 3. Every backlash event has exactly two options: accept the negative effect, or pay an alternative resource and call `tv_govhouse_reduce_power_balance_effect` to lower the balance by 5 percentage points. Tier 2 adds rare art/artist losses; tier 3 upgrades the local satisfaction loss to an area-wide effect and adds a cabinet crisis. The Governor's House GUI shows right-aligned fixed-width 25/50/75/100% markers and four warning rows below the Balance of Power bar for the <25, 25-49, 50-74, and 75-100 segments.

Grand General replacement cost note: generated Remove/Change Grand General actions call `tv_govhouse_pay_grand_general_replacement_cost_effect` before resetting `tv_govhouse_power_consolidation`; the cost is Government Power equal to `tv_govhouse_power_consolidation * 20`, so a fully consolidated Grand General costs 20 government power to remove or replace.

## IO Architecture Design Decisions

The character-led TV IOs (`tv_arts_exhibition`, `tv_diplomatic_alliance`, `tv_academy_of_sciences`, `tv_govhouse`, `tv_engineering_department`) share invariants that must never be broken.

### 1. leader_country = founding country, locked at creation

`on_creation = { set_leader_country = scope:actor }` runs once when the IO is created. `leader_country` is not reassigned by normal gameplay afterward; the only exception is the manual recovery action `tv_reinitialize_mod`, exposed at the top of the Victory Situation panel, which recreates missing victory-path IOs where possible and reassigns joined TV IO instances back to the current country. It controls IO permissions, `is_leader_of_international_organization` trigger, and `leader_country.modifier:` chained access in `monthly_change` scripted values.

### 2. No elections — leader_change_trigger_type = none is mandatory

All TV character-led IO type definitions keep `leader_change_trigger_type = none` and `leader_change_method = none`. These prevent the engine from reassigning `leader_country` automatically. `international_organization_chooses_new_leader` is **globally banned** from all TV IO-related code — this effect triggers the vanilla election process. Any call to it violates the no-elections design and risks silently reassigning `leader_country` to a different country.

### 3. Great person characters are independent country variables, not the vanilla ruler

The character displayed in the IO header is stored as a country variable on the `leader_country`:
- Arts Exhibition: `tv_arts_exhibition_leader_char`
- Diplomatic Alliance: `tv_diplomatic_alliance_leader_char`
- Academy of Sciences: `tv_academy_leader_char`
- Governor's House: `tv_conquest_general_char`
- Engineering Department: `tv_great_engineer_char`

These are set/cleared exclusively by the generated generic actions in `tv_io_leader_actions.txt`. The vanilla `leader_country.GetGovernment.GetRuler` and `appointed_leader.*` are different concepts and must not be used in TV IO calculations.

### 4. IO variable monthly_change uses chained character attribute access

All IO variable `monthly_change` scripted values that depend on the appointed great person must use `leader_country.var:tv_xxx_leader_char.attribute` chained access — never `appointed_leader.attribute`. Examples:
- CORRECT: `value = leader_country.var:tv_academy_leader_char.adm`
- FORBIDDEN: `value = appointed_leader.adm`

### 5. Header display uses blockoverride

All character-led IO panels use `blockoverride` on their header template to display the appointed character (read from the country variable via `GetPlayer.MakeScope.GetVariable(...).GetCharacter`). Never use the vanilla `GetLeaderCountry.GetGovernment.GetRulerOrRegent` accessor chain.

### 6. All TV IOs have unique = no

Each country pursuing the relevant victory path creates its own independent IO instance. The `international_organization:type_name` scope link is **invalid** for non-unique types. Always use `every_international_organizations_member_of = { limit = { international_organization_type = international_organization_type:<io_type> } ... }`.
